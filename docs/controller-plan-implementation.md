# 控制器结构实施记录

## 阶段与验证

1. RunStore：项目 logs/<run_id> 建立 run.json、事件历史、逐实际任务状态和产物映射。路径优先相对项目，文件存在性为登记时观察，不是结果验收。345项普通测试通过。
2. 结果核对：显式会话恢复之后，HOM对相同参数/任务名及工程+后处理+CST后端指纹的接收记录进行核对；快照SHA-256必须匹配。多条匹配拒绝自动选择；匹配结果接力到新Worker，不再次求解。算法写检查点后再标记 algorithm_adopted。346项通过。
3. 身份与状态：逻辑job_id由名称、参数及执行定义生成；实际task_id随每次提交变化，attempt_no记录Manager重试。RunStore拒绝非法状态转移；状态快照为权威索引，JSONL是辅助历史，两者不是跨文件事务。348项通过。
4. 集中观察：应用日志及Worker stdout、生命周期、故障、原生阶段、资源和接收记录集中到 logs/<run_id>。task/ack/stop、PID和工作副本仍在temp；恢复记录引用原会话，历史temp布局仍可查询。独立测试工具未提供run_directory时保留原布局。349项通过。
5. 资源与排空：默认每任务预计1线程、1GiB，另留512MiB可用内存；启动前检查整个池预算，派发前检查活动预算。可通过CSTManager(resource_budget=ResourceBudget(...))按实际模型设置。拒绝时暂停，不派发、不用Worker重启掩盖资源不足。旧Worker先DRAINING、安全关闭后RESTARTING；关闭失败不创建替代会话。351项普通测试通过，最终复核结果另记录。

## 范围与限制

最终回归：352 passed / 19 deselected；增加旧Worker排空失败禁止重建的测试。五个阶段分别提交；此前未提交的协议/观察工作另有基础提交。

- 调度预算是估计，既不绑定CST线程数，也不提供OS硬内存隔离；必须按模型实际消耗调整。没有引入集群、消息队列或数据库。
- 单控制器项目锁仍有效；RunStore多实例之间不具有分布式锁语义，写同一任务索引仍由单任务负责。
- 旧版received记录缺少执行指纹或快照摘要时不会自动复用，须人工核对。没有将旧文件自动搬迁或删除。
- 已检查点接纳的结果不再次复用；恢复时快照与必需指标仍通过既有HOM校验，不能只凭Completion成功接受。
- 真实CST锁故障、保存异常、长时内存保护、原生进度和生产恢复均尚未针对本次全部改动重跑；普通测试不代替端到端验收。
- 不清理活跃temp或接收记录。压缩包尚未更新，Git推送需用户另行要求。
