# GUI日志保留与任务状态恢复

日期：2026-10-15。本轮不启动真实CST。

## 使用与行为

- 删除“清空日志”按钮及对应Handler/事件模型的clear方法；运行、停止、恢复、重连和切换项目均不主动清空已显示日志。筛选只改变可见项，不删除缓存。
- 选择已有项目后自动连接Runner，先显示已保存状态与检查点摘要，再分批回放日志。仅查看/恢复显示不会提交start、recover或求解；实际续算/残留会话恢复仍须用户明确操作。
- 恢复覆盖边界、已接收模式数，以及已有的标准任务完成数/总数。覆盖边界来自检查点，不拿最高模式频率冒充进度；缺失字段不猜测。
- Runner重启保留上一状态、会话安全、错误、日志目录及历史目录；原活动状态仍转为RECOVERY_REQUIRED，而不是恢复成“正在计算”。控制租约不继承。
- 旧项目没有Runner日志指针时，首次启动发现项目logs直接子目录内的application.jsonl，按目录名稳定排序回放；这不证明旧随机目录的实际运行时间顺序。不会递归扫描模型/结果大目录。
- 回放保留原timestamp、source和context。当前GUI消息不因旧消息进入而整屏消失；新运行或Runner重启保留已有source游标，避免反复重播同一批历史。

## API与实现

Runner.status新增/保留log_history列表，每项directory及可用的run_id；新日志目录取代旧目录时先登记旧位置。目录必须位于本项目内才可回放，不读取外部旧项目路径或越界链接。

GET /events仍为schema_version=2；cursor增加source（文件绝对路径，由服务端已登记目录中选择），客户端原样URL编码JSON传回。每次只读一个文件，最多256KiB、200事件，完成旧文件后移动到下一文件；不是把所有日志载入内存。旧无source游标从首个历史文件重新读一次；项目切换重置连接上下文。

GUI新增RunnerController.snapshot_changed和MainWindow.renderRunnerSnapshot；后台事实通过快照显示，不调用进程内Backend恢复接口。

历史文件丢失或尾行未写完时发可读提示并继续后续日志；日志权限/读错误仅产生诊断，同一游标相同错误不刷屏，不将已确认计算状态改成失败或未知。当前活跃文件的不完整短尾行仍等待补全。原日志和结果从不被清空/删除。

关闭/断开为幂等操作：对已断开的窗口再次close或detach直接接受，不再次打开确认框、释放控制权或向已关闭线程池提交操作。恢复窗口与后续窗口的Qt对象生命周期组合测试覆盖此边界。

## 性能与兼容边界

界面仍为最近5000条事件/5000行的有界镜像，队列和批量上限不变；本次没有改为无限内存历史。日志全量记录由磁盘log/JSONL保存，超出显示缓存的历史使用文件入口查看。回放大日志需要多次轮询，不承诺立即全部显示。普通本地GUI消息是否另有完整文件副本仍取决于原有文件Handler配置。

原.clear方法和clearLogButton属性已移除，内部调用方及测试已迁移，不保留可误用的清空兼容入口。后台API游标需由客户端原样传回，新服务端与旧GUI的游标语义不宜混用。
