# Worker 逐任务资源统计

普通应用日志默认 INFO：等待心跳每 10 分钟一次，开始、阶段变化、异常与结束继续及时记录。30 秒等待详情降为 DEBUG，可通过 `CstApplicationBackend(logging_level="debug")` 或注入 DEBUG logger 开启。资源 JSONL 的 30 秒采样不变；心跳间隔不是求解超时门限。GUI 继续沿用已有的阶段进度信号与原位显示，本次未新增 GUI 资源面板。

每次 `run_task` 在会话目录 `resource_usage/<独立记录ID>/` 保存：

- `samples.jsonl`：初始、等待期间每 30 秒以及结束时采样，记录 worker/session/job/task_id、UTC 时间、相对时长、CST 根进程与子进程的 RSS/private bytes、累计 CPU 时间及读写计数、系统总/可用内存和使用比例。
- `summary.json`：成功/失败、错误、运行时长、采样峰值、观测到的 CPU/读写增量、平均 CPU 利用率（单核 100%，多核可超过 100%）、采样数与错误数。应用日志输出摘要与记录路径。

统计范围是每次任务进入 Worker 后至退出（包括就绪等待、求解、读取、Ack 与存档），不包括 Manager 排队时间；异常和内存保护退出也保存摘要。启动前被拒绝的调用可能没有 task_id。记录留在会话目录，不随 CST 结果目录改名。

CPU/读写统计按 PID+创建时间跟踪增量，初次观察作为基线，避免把 Worker 之前的任务计入当前任务。短生命周期子进程、采样前后的瞬时峰值及初次观察前的工作可能遗漏，因此为采样估计/下界，而非操作系统精确计费。Windows 进程 I/O 字节数不等同于物理磁盘流量；RSS 求和可能重复计入共享页，private bytes 更适合内存保护分析。

未采样到数据使用 null，不将不可用资源伪报为零。采样/写入失败只记警告或计数，不改变原任务结果。统计和内存保护相互独立，关闭内存保护仍保留资源统计。依赖本地 psutil 环境；原发布包尚未包含本功能。
