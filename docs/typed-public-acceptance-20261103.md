## 发现及修正

1. 命令环境中 DesignEnvironment.new 曾连接超时；常规权限对照可创建。按PID接管又发现wmic缺失。后者是已证明的接管障碍，不是对最初超时唯一根因的断言。该原身份后来退出，仅按退出事实退役。
2. 空MWS通过 `-m -b` 没有执行Model.run，日志报缺少结构数据，退出却为0。仅补ChangeSolverType无效；模型器退出0不能替代完成标记。
3. 新对象两次RunScript时，第二次最小保存/标记脚本也未执行。改为一次脚本，先只读PID帧与父进程绑定，再进行参数/历史。没有用OpenFile/全局Active3D，也没有假定任意其它版本必然相同。
4. 多参数 `.Zrange` 的首参数以括号开头触发WinWrap Unexpected text；改为保持值不变的`0+`数值表达式前缀。参数引用仍保留，没有扁平化成常量。用户提供弹窗后点OK使失败宏返回；该候选保留，不重用半模型。
5. 结果已发布/RunStore已采用，但接收回执未更新algorithm_adopted，生命周期误报未消费。新增同一采用屏障补写，先验证任务/会话/值/快照和原生档案，再修复回执；恢复不重新求解、不改结果revision、不重复日志采用事件。
6. 原生Solid.DoesExist的CStr在本机输出`-1`，不能只接受文本True。按版本规则严格接受True/-1，不把任意非空字符串当True；原始值留档。

原始历史现单独保存history.vb及build-intent哈希，避免只能从长字符串宏还原。原生桥接日志区分脚本/失败候选保存/项目关闭/应用关闭；failure.json使等待进入退出预算而非重新等待一个空闲阶段。
