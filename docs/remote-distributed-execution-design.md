# 远程与分布式计算扩展设计

日期：2026-10-15。状态：前置设计，未实现或验收。

执行顺序统一以[实施计划E0–E9](execution-platform-implementation-plan.md)为准。
本文保留远程技术边界，第9节L/R编号仅保留历史映射，不独立维护TODO。

继承[GUI/Runner分离方案](gui-runner-process-separation-design.md)，本设计只规定扩展边界。
近期仍实现本机Runner，不开放远程端口，不部署调度平台，不修改CST/VBA ABI。

## 1. 三种能力必须区分

|能力|含义|不代表什么|
|---|---|---|
|远程查看/控制|GUI连接另一台机器的控制器|不是多节点计算|
|任务级分布式|独立任务分别在多台CST节点运行|不是单个求解器跨机并行|
|CST原生分布式求解|单次求解由CST自身并行机制执行|需另查版本、许可、求解器支持，不能由本项目调度接口自动获得|

第一阶段扩展目标为前两项；第三项不作支持承诺，未来以独立执行能力接入。

## 2. 分层架构

```text
GUI / CLI
    │ 控制请求与事件
Controller（运行策略、检查点、任务账本、唯一结果采用者）
    │ ExecutionBackend：提交、观察、停止、对账、工件登记
    ├─ LocalExecution → 本机Agent职责 → 现有Manager/Worker → CST
    └─ RemoteExecution → 节点Agent → 现有Manager/Worker → CST
```

本机阶段Controller与Agent职责可同处Runner进程，不提前拆成两个常驻服务。
后续远端Agent是节点执行服务，不是第二个HOM扫描控制器；扫描策略只在Controller运行。
原设计“每项目一Runner”对应每项目一个逻辑Controller，不要求每项目部署一套节点服务。
节点Agent可服务多个项目，但同一工作区/会话只能由一个有效任务尝试持有。

Controller掌握调度意图、配置和算法检查点；Agent掌握本机进程、工作区、资源与协议事实。
Controller不能仅凭节点失联宣布CST死亡，Agent不能自行推进全局扫描覆盖。
迁移时先梳理当前Manager混合的调度与本地进程职责，不将整个Backend任意方法变成远程RPC。

## 3. 任务模型与最小预留

本机实现即采用JSON可表达的数据对象，不传Python对象、pickle、Qt信号、回调或开发机绝对路径。
拟议字段如下，具体schema在实施时定版，不能当当前接口调用：

|字段|用途|
|---|---|
|schema_version / capabilities|版本协商与必需能力校验；不支持则明确拒绝|
|project_id / run_id|稳定逻辑项目及运行身份；路径不是身份|
|logical_task_id|一次业务计算身份；参数相同但需求不同不能混为一项|
|attempt_id / request_id|执行尝试及控制命令身份；重发不生成新尝试|
|node_id / agent_instance_id|机器与本次Agent实例，不能用PID替代|
|owner_epoch|所有权代次，阻止旧控制器结果改变当前状态|
|input_refs / execution_fingerprint|输入、表达式、后处理及mesh/求解策略的不可变描述与哈希|
|resource_requirements|内存、CPU、磁盘、CST版本及许可需求；未校准估计明确标识|
|affinity / dependencies|Warm会话/节点偏好和快照依赖；不是跨机热迁移|

本机路径仍可作为node_id限定的物理位置，但逻辑命令用工件引用。
幂等键与内容哈希分开；内容哈希用于校验，不取代任务身份。
执行指纹需版本化，包含会影响结果的CST版本、宏/后处理定义、输入及设置；不可只比文件名。

ExecutionBackend只预留提交、状态/事件、停止、结果对账与工件解析这些必要操作。
不强迫现有所有方法适配统一大接口；先完成Local实现，再以契约测试验证Remote实现。

## 4. HOM分布式边界

单条自适应HOM扫描默认仍串行：窄区间nmodes=1，后续窗口及Warm快照依赖前一步结果。
不能为了“分布式”自动放大区间、提高nmodes或同时计算未知的下一步。
优先并行互相独立的标准参数任务、独立工程或多个独立扫描链。

Warm链优先留在同节点同会话，避免mesh重建和大型工件搬运。
一条链中断换节点时从已验证快照冷恢复，性能不能描述为Warm迁移。
未来若允许用户显式分片扫频，必须另验收边界重叠、退简并/重复模式、失败空洞、覆盖合并及场匹配；
不在首版自动实现。跨节点的场匹配还需共同物理域、材料/几何掩码、体积权重及坐标身份核对。

## 5. 权威状态、租约与网络分区

状态链建议为：排队 → 节点接受并持久化 → 运行 → 本地完成待同步 → 工件验证
→ Controller接受 → 算法检查点采用。重试必须产生新attempt_id，不能覆写旧尝试。
节点心跳用于观察，租约用于控制授权，两者均不代表CST完成或死亡。

失联默认策略：Agent可完成已接受的当前任务、保存结果，不再自行扩展任务；
Controller将状态标为未知/失联，不将其当失败重发。Agent恢复连接后先对账。
租约失效或控制器身份改变时，Agent在安全步骤停止新派发并标准收尾；
阻塞Solver期间允许等返回，不能用租约到期作为强杀理由。

owner_epoch由唯一权威持久化递增，Agent校验并拒绝旧代次新命令，Controller拒绝旧代次结果直接采用。
但fencing仅能防止旧结果写入权威状态，不能保证已运行CST立即停止或不占许可证。
未确认旧尝试已关闭/死亡时，默认不得在另一节点重复执行同一业务任务。
首版不支持多Controller高可用或网络分区自动接管；人工恢复也须先核实旧控制器及执行尝试。
不能用共享目录lock文件、PID或时钟时间戳实现跨机共识。

## 6. 工件与数据位置

定义ArtifactRef：工件身份、类型、大小、内容哈希、产生任务/尝试、位置列表和可用状态。
位置可为某node_id的本地路径、受控共享存储路径或后续对象存储键；不能假定服务器F盘存在于客户端。
采用受控路径映射与相对路径，不接受客户端任意路径穿越。共享目录只是存储，不是任务所有权系统。

输入以只读快照和manifest下发，节点在独立工作区执行；表达式和历史块保留。
工程.cst与同名结果目录需作为关联工件集描述，不能把“有.cst”当“场数据齐全”。
工件通过临时位置上传/复制，校验哈希后原子发布manifest，未发布完整集不能作为成功结果。
完成计算、工件在节点可用、已复制到持久存储、Controller已接受分别记录。
节点本地有结果但节点丢失时不能宣称中心已有可恢复结果。

优先在数据所在节点执行VBA积分或Python场分析，只传标量、模式描述、匹配摘要和必要抽样。
需要完整三维场时再按现有[算子执行方案](postprocess-operator-execution-plan.md)估算计算加准备/传输总成本。
不能为统一接口强制每次导出/传输大场。工件支持按需复制、校验缓存及保留策略，首版本机不需对象存储。
Agent收到明确持久化确认及保留条件满足后才清理恢复资产；GUI断开不触发清理。

## 7. 资源与许可

Agent报告支持的CST版本/可执行路径、求解与后处理能力、运行身份、本机并发上限和资源观测。
调度只选择满足任务要求的节点，不能悄悄替换版本或后处理算法。
默认每节点CST并发1，可调；节点总容量约束跨项目共享，不能每项目都认为自己独占机器。
许可证还可能是跨节点共享池：静态配置配额/准入只作上限，不声称等于许可证服务器实时可用数。
许可拒绝须分类诊断，避免无限重试风暴；不将许可等待误判为求解失败或空频段。
保留现有Worker运行次数回收、资源统计与内存异常诊断；跨节点日志补node_id/attempt_id。
正常求解仍无固定总超时；连接、命令、启动/退出及传输无进展检测有界，失联不等于取消成功。

## 8. 安全与部署边界

本机回环令牌协议不能直接把bind改为0.0.0.0后上线。远程需TLS、认证、项目级授权、审计和凭据轮换。
优先节点向控制器发起认证连接/拉取任务，避免要求每台Windows节点暴露入站端口。
首个远程原型可在明确授权下使用受保护隧道，但不等同生产安全验收。
不允许任意shell或不可信客户端上传宏直接执行；CST宏本身具执行能力，必须有可信任务来源、路径限制和输入审核策略。
Agent以明确用户身份运行，不能把别人的CST进程、许可证会话和工作区当本项目资源。
节点创建时间/实例代次按本地事实判断，日志统一UTC并记录节点时间信息；排序采用版本/游标，不依赖跨机时钟精确同步。

## 9. 阶段计划与验收

|阶段|范围|门禁|
|---|---|---|
|L0近期预留|明确Controller/执行边界、序列化对象、工件引用、实例身份|本机契约测试，不引入远程服务|
|L1本机落地|完成原方案P0–P6，独立Runner及崩溃对账|GUI终止不影响计算，Runner恢复不盲重算|
|R1远程控制|一GUI控制单远端Runner，认证连接及重连|断网不误停止、不重复命令、权限隔离|
|R2单远端Agent|Controller/Agent职责分开，先假Worker|失联、重启、旧代次、响应丢失和工件断传|
|R3多节点独立任务|节点准入、总容量、许可配额、数据亲和|不超配、不重复采用、节点间结果隔离|
|R4真实CST验收|逐版本串行副本、Warm亲和/恢复及性能对照|结果/后处理/协议/退出皆核验|

各阶段测试须覆盖控制器和Agent分别崩溃、网络双向/单向断开、迟到命令/结果、重复完成、
同ID异内容、磁盘满、原始场缺失、哈希失败、权限拒绝、共享许可证不足、多GUI控制权冲突。
节点丢失时明确区分已持久复制资产与节点唯一资产；禁止把旧测试数用作分布式验收。
真实网络/节点部署和CST求解均需后续明确授权，本设计不授权启动服务、开端口或传输用户工程。

## 10. 当前实现映射与约束

复用入口见[原方案第12节](gui-runner-process-separation-design.md)。现有RunStore和JSON/文件协议为单控制器本地实现，
ProjectRunLock为本机所有权保护，result_reconciliation仍读取本地路径；均不是现成分布式实现。
后续优先改边界及工件解析，不直接把这些目录挂共享盘后宣布支持多节点。
当前没有RemoteExecution、节点Agent、跨机租约或TLS控制接口；本文字段和阶段均为拟议设计。
