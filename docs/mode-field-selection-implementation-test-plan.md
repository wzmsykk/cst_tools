# COMSOL式场匹配：实现与验收计划

日期：2026-10-13。依据：[算子流程选择](postprocess-operator-execution-plan.md)、[效率验收](cst-field-efficiency-acceptance-20261013.md)、[COMSOL方法摘要](../knowledge-base/comsol-eigenmode-tracking.md)。范围是参考场匹配及极化模族诊断；本文不表示功能已实现。

## 1. 目标与不变边界

实现：参考快照/模式→场数据或小矩阵→重叠计算→匹配/未确认→对应原始后处理结果。

不做：改求解器、把HOM默认改为多mode、自动证明失败区间为空、重写R/Q物理算法、删除相近频率、把真实分裂模式混成新的本征模。

先作为可选诊断运行，不改变HOM已接受模式、扫描游标和检查点。诊断验收通过后，才能另行决定是否用于自动模式接收。

## 2. 先选数学目标，再选最快路线

| 目标 | 第一实现 | 必须通过的门禁 | 未验收优化 |
|---|---|---|---|
|同网格等权数组相似度|原生Result3D→Gram/交叉项→Python MAC|同网格身份、共轭、对象变异及数值误差|批量重用对象/范数|
|跨网格固定域采样相似度|原生HDF5公共点→Python加权Gram/MAC|坐标/单位/域/权重/无效点一致，采样收敛|公共点→SetArray→原生小矩阵|
|近简并组身份|正确Gram/交叉矩阵→Python有效秩白化/SVD|完整模组、秩与条件数、子空间稳定、匹配歧义|分块与多组矩阵批处理|
|完整体积重叠|共同域的可靠求积与插值→同上|全域几何支持、权重和采样误差验收|可靠原生加权积分接口|
|束流方向/极化解释|多方位路径复电压→Python分析|路径/偏移/相位/归一化一致|仅输出小极化矩阵|

原生等权索引和不是体积积分；小ROI相似度也不是全场模族证明。输出必须带 `metric_kind` 和 `scope`，禁止二者共用“已证明相同模式”标签。

## 3. 最小数据及接口

建议新增小模块 `csttool/mode_matching.py`（纯NumPy计算）、`csttool/field_artifacts.py`（HDF5与元数据读取）。CST导出通过现有 `postprocess_cst.py` 注册一个明确的场工件方法，不启动新后端框架，不扩展控制协议承载大数组。

### 3.1 工件

- `FieldArtifact`：场文件路径、校验摘要、任务/会话/快照身份、原始mode编号与频率、E/H类别、坐标/场单位、采样定义摘要、权重/掩码摘要、实际精度。
- `SamplingSpec`：坐标系、域范围、点集及生成版本、求积规则、几何支持与无效点策略。定长矩形网格中心求积可用统一体积权重；任意点列表没有天然体积权重。
- `OverlapMatrices`：复数 `G_ref`、`G_candidate`、`C`，与原始mode列表、相同内积/域身份；序列化实部和虚部，不丢相位。
- `MatchReport`：MAC矩阵、范数、匹配候选及分数/差值、有效秩和子空间奇异值、状态与原因、原始结果映射。极化方向不是匹配标签的别名。

场身份不能仅靠.cst哈希；场在同名结果目录中，还需实际场源/结果身份。一次任务准备时建立身份，随后复用，不为每个矩阵元素重新读盘或计算文件哈希。

### 3.2 纯计算入口

`weighted_overlap(reference, candidates, weights)` → G_ref/G_candidate/C。

`normalized_mac(matrices)` → MAC与有效性诊断。

`match_modes(mac, frequencies, policy)` → 一对一匹配或未确认。

`compare_subspaces(matrices, policy)` → 有效秩、主角度/奇异值及组级状态。

初期只支持明确的一组参考和候选；不做通用算子图、插件发现、自动硬件调优或多profile体系。

## 4. 分阶段实施与退出条件

### M0：离线数值核心与合成安全网

实现加权内积、MAC、单参考筛选和矩阵/元数据验证。仅需要NumPy，CST不参与。

退出条件：下方N类测试全通过；空场、非有限值和身份不一致明确失败；歧义明确未确认。默认匹配阈值不得未经实测直接采用COMSOL示例0.5。

### M1：公共点原生小矩阵路线效率验收

实现独立测试宏：VectorPlot3D批量采样→Result3D.Initialize/SetArray→显式Conjugate/DotProduct→输出小矩阵；不将VBA解释器循环作为正式累计方法。

与现有原生HDF5＋Python使用同一参考/候选、同坐标、同权重、同数据精度对照。加权时需验证sqrt(W)转换正确，转换时间计入。跨快照时，参考场从哪里获得、加载/切换工程耗时也计入；不能只测当前工程内两个模式就证明跨网格路线最快。

退出条件：正确性一致、正常退出、源保护；形成同语义流水线的耗时/内存报告。胜出前仍保留HDF5路线，不宣称候选最优。

### M2：可靠场导出及工件读取

实现正式场工件注册、原生HDF5读取和采样元数据。导出必须在求解结果仍有效时完成，不修改参数、不Rebuild。只复制.cst适用于新求解；复用旧场要让同名结果目录可访问，或CST带结果另存。

先以现有cell=30/36快照做跨网格试验。矩形点集从相同物理域开始；共同点坐标一致后才能比较。优先验证CST原生对指定点的插值，不自行重复插值同一数据。

退出条件：E/H复分量、单位、位置、点数及无效点策略验收，工件原子发布并纳入既有任务工件映射。HDF5依赖在可选场分析功能中声明/延迟加载，不让未启用用户被迫导出场。

### M3：跨网格单模匹配及采样精度门禁

实现公共域求积与单模MAC报告。对12³/24³/48³及必要更密点集，比较矩阵稳定性与匹配结果，而不只比较后处理标量。

ROI可以先做快速筛选，但正式模族判断必须在有代表性、经验收的域上确认；局部相关性高不能替代全域确认。低重叠、多个候选近似同分、范围缺失时返回未确认。

退出条件：受控解析场及真实跨网格对照通过；输出置信度依据及域局限。当前5%R/Q容差不能直接作为MAC或求积误差阈值。

### M4：极化模组、子空间及一对一配对

对完整模组计算G/C，检查Hermitian一致性与数值正定性；用有效秩白化/SVD比较子空间。组内允许基旋转，但不修改原始本征频率和逐mode物理结果。

先支持2维极化候选组；分组来源由用户指定或标记为待确认候选，不仅凭频率接近自动确诊。组内个体无法唯一识别时，可输出“模族匹配、成员未确认”。

一对一配对必须允许拒绝：2mode可用两种排列直接比较；更多模式再评估可靠的分配实现及依赖。匹配总分接近或个体分数不足时不强制分配。

退出条件：旋转、换序、漏模、混入第三模、秩亏和真实分裂案例均能区分；至少一个真实跨网格极化对通过场证据验证。没有这项证据不能将cell=30升级为极化方向收敛基准。

### M5：可选诊断集成与恢复验收

接入ManagedWorker完成阶段和既有run/artifact索引；Python在确认工件完整后分析，结果记录独立于原始求解成功状态。

求解成功但诊断失败：保存求解快照/结果，标记诊断未完成；从已保存工件重试分析，不默认重算。诊断属于明确必需项时再由现有任务策略决定不完整状态。不得用大文件导出失败覆盖原求解证据。

退出条件：故障测试F类通过、标准Stop/Quit无残留、HOM单模回归未改变。GUI只增加诊断状态/证据路径，不在本阶段重构GUI。

多方位复电压作为M4之后的独立扩展，解释方向性R/Q，不阻塞最小场匹配闭环。

## 5. 正确性测试矩阵

| 编号 | 构造/输入 | 期望 |
|---|---|---|
|N1|同场；非零复幅度/相位缩放|MAC=1，幅度相位不改变身份|
|N2|正交复场|MAC≈0；近零交叉项使用范数尺度绝对误差|
|N3|a=1+i，b=2+3i|Hermitian项5+i；未共轭-1+5i被检出|
|N4|非均匀正权重、解析可积场|与独立解析结果一致；不能退化为无权重和|
|N5|零场、NaN/Inf、负权重、形状/单位不一致|拒绝，不返回看似有效的MAC|
|N6|频率排序交换、分量/点顺序交换|模式换序可配对；点顺序错误先拒绝或显式重排|
|N7|两个正交参考的45°旋转基|单参考可能歧义；二维子空间匹配|
|N8|随机酉旋转、相位、排列|组级结果不变；不自动确定物理极化角|
|N9|缺少一个成员、重复列、近秩亏、混入第三模|秩/维数不符或子空间不匹配，不静默降维宣布成功|
|N10|Gram轻微浮点非Hermitian/轻微负特征值，及明显错误|仅容许误差预算内修正；明显问题拒绝|
|N11|同样点数但不同坐标/网格/域支持|不能按长度直接点乘|
|N12|正交dipole、旋转积分位置和极化方向|单线R/Q可近零/最大；总和不作为位置不变量或成员身份|
|N13|两个候选都过阈值且分数接近|输出歧义，不任选Mode 1|
|N14|MAC稍超[0,1]与明显越界|仅舍入误差范围可裁剪，明显越界拒绝|

浮点纯计算可用1e-10级合成一致性检查；原生算子本轮实测范数尺度误差约6.9e-10，探针门禁1e-6。二者不是物理匹配阈值。物理误差预算与拒绝门限由M3/M4校准并记录，不能混用。

## 6. 真实CST与效率验收

| 编号 | 测试 | 计时/验收边界 |
|---|---|---|
|C1|同网格原生点乘及共轭|已通过；复用现有证据并加入正式接口回归|
|C2|公共点SetArray原生累计 vs HDF5/Python|同点同权重；包含取场、分量转换、对象复制、导出及读取|
|C3|cell=30与36结果跨网格比较|两份快照及结果目录；不重新求解；记录参考加载成本|
|C4|对称解析Pillbox及受控不对称案例|验证物理模族/极化判断；新求解源保护及固定求解配置|
|C5|采样域、密度与边界点改变|识别局部域误判；无效点不能静默改为零|
|P1|3档点数、2mode，至少3次公平对照|轮换路线顺序，记录每次完整时间及阶段时间；小差异不宣称胜出|
|P2|多mode批量|一次加载/转换复用；测矩阵累计及峰值内存；不重复每对导出|
|P3|已有Worker、离线打开、已缓存场三场景|分别测增量与完整墙钟；冷/热状态明确，不混为一项|

不强行清系统缓存或结束无关进程。无法控制的后台负载与缓存状态留档；场景P3若未完成，结果只覆盖已测场景。

正确性通过后再选较快路线。参考/候选数、N、源读取、采样、算子、写盘/读盘、模块冷加载、收尾及内存都留档。共享准备成本单列，批量按一次准备加多个增量算子计费。

## 7. 故障、协议与恢复测试

| 编号 | 故障注入 | 期望处理 |
|---|---|---|
|F1|HDF5仅写一半、缺数据集/分量|不发布完整工件，不生成匹配结论|
|F2|磁盘满、路径不可写、导出异常|保留求解证据；记录mode/路径/阶段；正常收尾|
|F3|源场目录缺失、快照或场身份变化|明确缺场/身份不符；不自动当空区间、不默认重算|
|F4|停止发生于导出/分析期间|阻止后续诊断提交；保留有效已完成工件，标准关闭CST|
|F5|求解成功→导出完成→Python崩溃|恢复仅重新分析，不重跑Solver、不重复接收模式|
|F6|旧会话/旧task的场或矩阵混入|按身份拒绝；不因文件名相同复用|
|F7|匹配歧义、秩亏、未完成候选组|状态未确认，可查看证据；不伪报计算异常或物理成功|
|F8|错误路径上的标准退出失败|按现有生命周期诊断处理；未证明标准方法失败前不强杀|

复用当前Task/Completion/Ack机制；大场只写工件并登记路径/摘要，控制文件不放数组。工件完整性确认和Ack/任务状态职责分离，不能把每次分析故障重新引入协议重试或求解重放。

## 8. 日志与交付

统一文本＋JSONL日志中记录：run/job/task/session、参考和候选快照及mode、采样/权重身份、算子/路线、阶段时间、文件字节数、有效点数、范数、误差、矩阵/工件路径、匹配状态及原因。大型矩阵和场写工件，不逐点刷日志。

每阶段交付代码/宏、离线测试、真实验收记录（有则附）、原始证据索引及未通过项。测试探针与正式接口分开；不将当前固定路径/ROI试验脚本原样变成产品功能。

实施顺序：**M0 → M1 → M2 → M3 → M4 → M5**。M1未胜出仍可继续M2；M3精度未通过不能将M4接入自动接收。每阶段验证后再进行用户授权的提交，不将设计记录当作已经通过运行验收。
