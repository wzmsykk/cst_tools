# HOM主工作台与详细运行信息

2026-10-25。主窗口默认显示“HOM 扫频与结果”，完整日志、Worker/CST局部进度、后台连接/控制权和后台管理放入“详细运行信息”。不删日志、不降低持久日志级别、不改Manager/Worker/协议控制行为；是显示层分工。

## 默认工作台

- 显示扫描目标、当前/最近计算区间、已确认覆盖前沿、已计算上界、模式数量、待处理/未解决区间。
- 覆盖条按(confirmed_frontier-start)/(stop-start)计算并限制0–100%；不是最大模式频率，也不是CST局部读数。两种覆盖边界单独标注，不因找到新模式就假定无空洞覆盖。没有有效目标/覆盖时不猜百分比。
- 模式表来自save/csv/hom_scan_checkpoint.json中的report.modes，显示全局顺序、频率MHz及原values指标；不按日志文本猜模式，不按频率重新去重，不将每任务mode_index=1误当扫描总序号。数字仅显示约10位有效位，不修改存储值/单位/模式判别。
- 检查点尚未产生时可显示当前“配置目标”，明确以运行检查点为准。启动/继续前不会把配置范围视为已执行。标准批任务没有HOM检查点时不会伪造HOM结果，标准任务详情仍在详细页。
- 顶部保留“导出失败日志”，正常页无需展开日志即可收集证据。异常摘要仍在主界面提示，堆栈/源码位置和完整错误留在详细日志；不会因收起详细页而放松恢复、控制权或关闭门禁。

## 详细页

完整结构化事件表/筛选/详情、原始日志、CST Worker身份与原始阶段/来源/局部百分比均保留。后台管理与申请控制权按钮移到此页；连接/Manager等运行信息不再不断覆盖主工作台状态栏。连接或控制权异常时主界面提示去详细页处理，不自动切换页、不抢焦点。停止/恢复/退出确认及退出失败横幅保持原行为。

原ui_main.ui/ui_main.py仍提供基础框架，MainWindow初始化时把原runSummaryFrame和日志区域装入详细页，避免修改生成文件导致下次生成丢失功能。配置区并发数/CST版本属于输入配置，保留在左侧；运行时PID/实例/会话状态属于详细信息。

## 数据路径和性能

GUI RunnerController._observe在现有串行通信线程中附加本地hom_display观察，HomDisplayReader只读检查点；缓存按规范项目路径、mtime_ns和大小，不变时不反复解析。沿用项目/连接代次门禁，旧项目返回不会覆盖新项目。只展示，不发start/recover/Solver；不新增HTTP响应字段或持久协议，hom_display仅为本地GUI快照附加值。当前不是远程结果下载API。

Qt表格使用QAbstractTableModel，仅检查点身份变化时重建模型，不按轮询逐个创建单元格控件、不自动逐次测量所有列。文件读取上限16MiB，最多显示最近5000个模式、前32项指标，超限明确说明，原始结果不裁剪。大表通过滚动查看，源文件变化才重新取指标集合。缺失/损坏/过大只影响显示，不触发恢复/重算；同项目保留上次表格并标注历史结果。项目切换立即清空旧表，取消文件夹选择保留原项目。读取错误技术细节放详细页，主界面给简短说明。

已有本地文件读取会占用串行观察线程，慢网络映射盘不提供硬IO超时；当前不宣称远程实时结果已接入。超过显示上限或无权读取须从结果/诊断文件核对完整内容。
