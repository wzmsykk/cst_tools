# GUI长日志显示与性能

2026-10-14，适用于GUI/log_view.py的QPlainTextEditLogger。

主窗口现默认使用[结构化事件表](gui-structured-log.md)，本文机制仍用于原始日志标签；事件队列另有界，不影响文件日志。关闭时停止GUI定时器，已排队回调先检查disposed，避免访问已销毁Qt控件。

原实现已有5000个文本块上限，但逐条信号/appendPlainText和自动换行会增加事件及布局开销。此为源码确认的性能风险，不是已在用户服务器现场测得的卡顿归因。

现实现使用线程安全队列，积压期间只发一次唤醒；GUI每批最多128条，后续批间隔30ms，拖动滚动条时暂停追加。向上滚动不拉回底部；回到底部恢复跟随。原生纯文本控件禁用撤销和自动换行，长行可横向查看，无额外动画或主线程文件读取。

显示仍保留最近5000行；待显示最多2000条，每条显示最多4096字符。洪峰时省略旧显示记录并提示数量，超长消息显示截断提示。限制仅作用于GUI镜像，不修改LogRecord，不改变log/JSONL文件输出；完整详情请查看已配置的文件日志。若程序未配置文件handler，不能保证界面省略内容另有完整副本。

清空按钮同步清空待显示队列，避免清空后旧日志又出现；关闭handler停止接收，队列释放，不操作CST或任务。窗口回收沿用现有removeHandler/close流程。

源码从main_window移至log_view，main_window保留导入名以兼容原调用。日志刷新是异步的，测试应处理GUI事件或主动flush_pending；不再承诺emit后立即可读。历史被淘汰时只可锚定仍在缓存内的内容。
