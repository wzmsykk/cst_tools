# WinWrap 代码生成的语法防线

日期：2026-11-03。状态：W0核心及受限Sub-only扩展校准通过，W1定义构造共享发射器已实现并经无求解副本/G03核验；W2/W3受限A1保存链也已实施，现行实现与边界见[W23实施](winwrap-w23-implementation.md)。对应[类型化服务](typed-definition-service.md)、[实际故障记录](typed-public-acceptance-20261103.md)。这不是把WinWrap语法错误当作正常求解失败后重试的方案。

## 问题归属

本次Unexpected text是生成器缺陷。Python的表达式AST合法，不等于它在WinWrap方法调用位置构成合法语句。现有project_history检查设置含义、允许命令和算术值，不是WinWrap编译器；假Worker也不执行WinWrap。用这些检查证明原生语法正确，超出了证据范围。

现有0+前缀已在本例实际通过，短期保留以免破坏已验链；它是局部修复，不是后续所有调用点的语法规范。首先固定语法和宿主契约，再替换；不依据通用VBA常识直接批量改写为另一种调用形式。

## 统一执行边界（按同类源码分析修订）

目标统一链：MCP/GUI/CLI → 同一ApplicationService类型化操作 → 输入/对象身份/版本校验 → 现有Runner执行槽 → 官方直接接口或历史发射 → 原生观察/G03 → 发布定义或采用结果。MCP层不组织临时VBA，也不另建解释器、队列或会话管理器。

|操作类别|选择规则|完成证据|
|---|---|---|
|参数和表达式数据|通过已核实的参数接口传值，保留表达式；参数表持久性单独验证|表达式读回、保存重开；不可只比较当前数值|
|需Rebuild重放的几何/设置|统一生成AddToHistory；直接调用只有在文档及校准证明同等持久性时才替代|历史记录、保存重开/必要Rebuild及G03核对|
|查询、会话控制、运行时后处理|优先已核实的官方直接接口或固定已验VBA模块；调用卡片声明副作用|真实返回、目标身份和对应产物/收尾证据|
|单次求解|先冻结工程/求解器身份，再由现有Worker提交；名称解析与求解异常分开|实际结果、Completion/ACK、RunStore采用和收尾；不凭Start返回值发布|

根base系列CLI和既有GUI/HOM还未全部迁入公共ApplicationService；以上是迁移目标及选择原则，不预先认定任何CST方法具有持久性。调用卡片从现有允许表补字段：所属对象/scope、调用类别、参数与单位/表达式规则、返回与失败含义、历史要求、副作用、版本、文档及校准来源；不另建第二份方法注册表。首批仅覆盖当前定义构造所用方法。

### 失败与恢复不变量

- 全部修改发生在未发布候选；任一必需属性失败即停止发布，即使工程保存成功。旧定义和已确认结果保持有效；当前候选的会话关闭与诊断继续按已有生命周期处理。
- 参数或对象身份错误、生成语法错误、历史执行错误、原生验证不符、实际求解失败分别记录。仅已有策略明确支持的实际求解失败可进入HOM加密/扩窗；不能用笼统异常触发重算。
- 同一执行尝试只派发一次求解；身份解析失败在求解前返回。响应丢失先对账，禁止因标签失败、超时或缺少回执再次调用Start；显式恢复策略的新尝试沿用现有任务/RunStore身份记录。
- 停止请求、宿主已停止、保存完成、收尾回执和进程退出分别传播。等待超时保留未确认事实及恢复入口，不标记取消成功或关闭成功，不用强杀消除不确定性。

## W0：固定语言、调用形式和编译边界

- 基线是本项目实际的WWB-COM/WinWrap Basic v9与CST2022宿主，不以VB.NET、Excel VBA或第三方Basic解析器代替。
- 查本地WinWrap语言帮助及CST方法文档，确认Sub调用、函数调用、属性访问、With成员调用、数组/ByRef、无参调用、声明、字符串与物理行限制。
- 固定一种经真实宿主证明的Sub多参调用形式。显式Call等只是待核实候选；不能再次凭语义选择语法。
- [W0文档核查](winwrap-w0-contract.md)已找到脚本级MacroCheckThis/MacroCheck原生检查候选，返回错误对象或Nothing；本机2022.5核心14样本已校准可调用、正反例、诊断Source与正文不执行；不是任意上下文/行列/初始化无副作用保证。控件SyntaxCheck/ErrorLine属于嵌入开发接口，未证明CST暴露，且SyntaxCheck可能触发初始化事件；不承诺离线原生编译。
- 分开**外层控制宏**与**AddToHistory字符串里的内层程序**。外层编译通过不证明内层已编译。若宿主没有纯编译入口，内层需要在独立无结果工程中实际执行/重放验证，称为编译及执行门禁，不冒充纯编译。

## W1：统一受限语法发射

已新增csttool/winwrap_emitter.py，当前服务定义构造；其它动态生成点按后续门禁逐批迁移；不开发完整VBA编译器，不增加MCP服务或新的跨语言协议。

最小对象为数值表达式、字符串、方法调用、函数/属性表达式、赋值/声明与With块。参数表达式仍保存为CST参数数据；必须重建时求值的引用保留在历史，不能以当前数值替换。

所有参数在结构化节点中传入，统一序列化；业务代码不再自行拼“.Zrange ”、逗号、括号和引号。表达式发射必须知道它用于赋值右侧、函数参数还是Sub实参，不能把同一段任意加括号的文本用于所有上下文。

沿用现有字符串/Unicode与分段辅助，统一管理模块/过程中的声明表、大小写不敏感重名、保留名和生成器辅助符号。文件句柄、频率变量、宏函数等不能因拼接片段发生类型冲突。固定语言声明、Option Explicit和唯一Main。

现有允许表已有命令/参数个数；history_call_contract已补scope、调用类别、参数检查归属、返回/持久化/副作用及文档出处，供发射和历史检查共用，避免另维护一套互相漂移的接口定义。允许表核验仍不能独自承担编译正确性证明。

## W2：启动前的独立检查和回归（受限A1已实现）

1. 检查受限语法的调用形态、字符串闭合、声明/过程重名、块结构、物理行和续行预算；未知片段明确拒绝。通过只表示符合本项目受限生成规则。
2. 引入从真实WinWrap/CST保留的通过样本及本次失败样本，避免仅断言输出包含0+或仅由自己的解析器验证自己的输出。
3. 覆盖一元负号、嵌套算术、乘除/幂优先级、首参数括号、多参数、函数返回值、XYZ、引号/中文/长路径/长说明、声明冲突和辅助模块重复。
4. 生成多种受限表达式组合，分别检查数值含义和语句位置。数值测试不代替语法门禁，通用VB解析器也不授予WinWrap通过状态。

语法问题归为GENERATED_CODE_INVALID，区分outer-macro/history层；不是求解失败，不加密、不扩窗、不自动重试。

## W3：真实宿主和发布门禁（受限A1已接入）

生成器、模板、调用允许表变化时，串行运行最小真实宿主验收：正确3D作用域、外层宏、动态历史、参数表达式/说明、保存重开、正常关闭。只运行必要设置/几何，不调用Solver.Start；多参/负数/嵌套表达式作为固定回归。

记录CST/WinWrap语言profile、生成器/模板/调用表hash和实际输入样本。缓存仅证明该版本和样本，不证明所有输入；输入仍需受限语法校验，构造后仍需原有G03。正常业务运行不为每个HOM窗口另起一个CST做语法检查；稳定宏复用、任务参数作为数据传递。

首阶段必须同时有离线和真实宿主门禁，之后再替换0+局部补丁。不能因一次Pillbox成功就宣称所有生成器/算子/语言构造已通过。

## 诊断与源映射

保留原始history.vb、外层宏、hash及source-map.json；映射输入字段/操作 → 内层历史行 → 外层宏位置 → Python生成函数。错误至少给出阶段、文件、位置或原始语句和对应输入，不能只剩history rejected或最终超时。

继续核查CST支持的编译错误采集能力；在没有可靠接口前，不承诺所有模态错误框都能无交互处理。发布门禁应拦截生成器已支持范围内的语法缺陷，不能把人工点OK作为生产错误处理协议。

## 分阶段交付与验收矩阵

|阶段|交付范围/实现入口|必须验证|通过后才能做什么|
|---|---|---|---|
|W0|允许表/调用卡片、宿主语言profile、编译与诊断能力调查；先定位definition_editing及native_definition_builder|实际失败调用的文档解释；区分外层和内层；无纯编译API时写明替代门禁和未解决错误框边界|冻结最小发射规则；调查不扩大为任意脚本执行服务|
|W1|definition_editing.render_history/render_edit_macro共享小型发射器；复用固定模块和现有执行槽|结构化输入保留表达式；统一声明/转义；全部属性成功才发布；失败候选不改旧revision|只迁移已覆盖的定义构造，暂留其它稳定宏|
|W2|受限规则检查、源映射、事务与故障测试|原始Unexpected text反例、负号/括号/XYZ/Unicode/声明冲突；中途属性失败；身份解析失败零次求解；求解异常或响应丢失不隐式再Start；停止超时不伪报关闭|允许进入真实无求解副本验收，不能授予原生语法通过|
|W3|真实串行无求解宿主样本、保存重开与G03证据；正常关闭检查|外层/内层均验；历史重放及表达式保持；错误映射到输入/生成函数；副本关闭无遗留；同样本新旧数值/定义语义一致|逐批迁移其余动态生成点，每批重复相应门禁|

离线测试复用definition_editing_test、native_definition_builder_test、definition_verifier_test以及现有single-simulation/生命周期故障测试的入口；实施时按实际新增行为补用例，不提前报告通过。真实宿主测试必须单独记录CST身份、生成器hash、样本、是否求解和退出事实。W3不为测试语言而调用求解器；真实求解异常继续归既有G03/G04故障矩阵，离线故障注入不能替代它。

每阶段同批同步本方案、类型化服务契约、TODO、当前状态和功能索引，执行文档索引及相应功能测试。调用卡片、winwrap_emitter与定义构造迁移已登记F126；后续新增实现同批维护。现有API保持不变；不为旧的手工字符串拼接提供新兼容层。

## 实施顺序与完成标准

W0调用规范/编译接口调查 → W1定义构造共享发射器 → W2独立检查/反例 → W3真实无求解门禁 → 迁移剩余动态宏生成点。既有稳定VBA模块不做无证据的全面语法改写。

完成后，本次原始失败语句必须在启动CST前被拒绝或由发射器结构性消除；对应表达式引用、数值和重建持久性保持不变；真实WinWrap门禁通过。W1/W2/W3已覆盖受限A1定义构造；其它生成点和完整语言仍按每批门禁迁移，不把首批副本样本当所有生成器通过。
