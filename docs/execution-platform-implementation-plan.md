## 1. 目标及最终结构

目标按顺序实现：GUI异常关闭不影响计算；控制器异常后可验证恢复；远程重连不重复提交；多节点执行独立任务。

```text
GUI / CLI
   │ 控制协议：命令、状态、事件
项目Controller（本机阶段驻于独立Runner）
   │ 算法、检查点、所有权、结果采用
ExecutionBackend
   ├─ LocalExecution → 本机执行职责 → 现有Manager/Worker → CST
   └─ RemoteExecution → 节点Agent → 现有Manager/Worker → CST
```

本机阶段Controller与执行职责同进程，不先部署Agent服务。后续节点Agent只执行任务，不独立运行全局HOM扫描策略。
一个项目一个逻辑Controller，一个活动运行；多个GUI可查看，修改控制权唯一。
单HOM链保持窄区间nmodes=1及Warm亲和，优先分发独立参数任务/工程/扫描链，不自动并行未知后续窗口。

## 2. 现在预留和现在不做

|本机实现必须采用|后续需求到达再实现|
|---|---|
|JSON可表达的命令/结果，不传Qt对象、pickle和任意方法调用|远端Agent服务、TLS远程部署|
|项目/运行/业务任务/尝试/命令/实例身份分开|跨机授权、租约和owner_epoch完整机制|
|任务配置不可变、执行指纹版本化|多节点容量/共享许可调度|
|工件引用与物理路径分开，位置带节点归属|文件传输、远端缓存/存储后端|
|执行边界与控制策略分开，可用假实现验证|多Controller高可用、自动故障接管暂不做|
|持久去重、崩溃对账、项目排他所有权|CST原生单求解跨机并行另行调研，不承诺支持|

不为预留能力引入消息队列、集群平台、数据库服务或新VBA ABI。
新增抽象应有本机调用者和契约测试，不提前创建空的多层框架。

## 4. 全阶段不可破坏的规则

1. GUI断开不取消任务；连接超时表示未知，命令接受不等于执行完成。
2. 停止意图先落盘，阻塞CST调用等返回后检查；正常求解无固定总超时，通信/启动/退出仍有界。
3. 控制器死后先确认身份及会话归属，标准停止/确认死会话，再对账恢复；不强杀、不热接管活跃CST派发新任务。
4. 覆盖以已确认区间和pending/失败缺口为准，不用最高模式频率代替；不从头覆盖旧结果。
5. 工程.cst与同名场目录分开核验；本地存在、持久复制、中心接受、算法采用是不同阶段。
6. 幂等防重复命令，结果对账防重复采用，不承诺exactly-once物理解算。
7. 心跳失效不证明进程死亡；fencing防旧结果采用，不保证已运行CST即时停止。身份未知不抢占。
8. 原子替换不自动保证断电持久性；关键保存失败停止新派发并保留诊断，不伪造成功。
9. 参数表达式、历史设置和运行时复杂后处理保持；不因抽象方便改成固定参数或强制导出全场。

## 5. 数据、日志和清理

沿用RunStore、received、检查点及可读日志目录，控制元数据与运行工件分开。
项目control目录记录实例、命令结果及可重建状态；仅持有实例信息不代表仍活跃。
Runner写计算日志，GUI写自身诊断；事件按游标分页和有界展示，恢复不依赖日志文本推断。
远端工件使用逻辑引用及哈希，物理位置限定node_id，不把客户端路径发送给别的机器直接使用。
保留可信快照、协议、接收记录和必要掩码，清理前核实任务结束及持久化状态；不删除活跃工作区。
原始场清理后说明需要重生成，不再声称旧场产物可用。

## 6. 验收组织

- 单元/契约：状态转移、命令去重、序列化、工件校验、未知归属和路径边界。
- 进程级假Worker：GUI和Runner分别终止，多GUI并发，所有事务窗口恢复，核对执行次数与完整覆盖。
- 网络故障：从E6开始验证响应丢失、断网、重连；E7以后补节点失联、代次变更和迟到结果。
- 真实CST：明确授权、串行副本、任务归属核实，不以Start返回1/退出0代替成功，不改原工程。
- 发布：从干净源码包启动，核对依赖/工作目录、后台生命周期和恢复入口。

文档索引通过仅证明入口有效，不证明这些功能已实施。现有GUI分批测试结果和Qt原生退出记录保留在
[GUI停止/退出文档](gui-stop-exit.md)，不能作为E1以后进程隔离验收。
