# 独立Runner及路径/持久化边界实测

日期：2026-10-15。

## 实测

- 真实CST2022 Pillbox副本在可读日志目录含中文时，预处理完成，但Managed宏按ASCII写出发生UnicodeEncodeError，CST Worker尚未启动。
  不能将预处理成功或Python退出作为任务成功。将字符串中的非ASCII字符转换为ChrW UTF-16单元表达后，真实单模标准任务、
  R=229/220双任务停止/续跑对照通过；原工程SHA256不变、未强杀CST。
- 单模cell8、500–800 MHz验收读到503.605585325746 MHz。它只是该网格/模型的输出，不是解析标准值或网格收敛结论。
- Windows并发读取检查点与原子替换曾出现WinError5；即使用带共享删除标志的文件句柄进行对照也未消除持有读句柄时的替换失败。
  改为取得短生命周期文本快照后解码，状态接口不反复打开活跃检查点，而由计算侧成功保存后发布摘要。
  JSON/INI发布仅在WinError5/32时有界重试同一文件替换，最多5次、总退避150ms；无求解或Ack语义重试。
- GUI完整离线回归曾在Qt测试阶段原生退出；让QApplication由整个pytest会话持有后，完整单进程回归恢复通过。
  该对照不充分证明原生退出只有一个根因，也不代表真实桌面交互已验收。
- 本机回环测试在执行沙箱内返回WinError10013，沙箱外相同假Runner测试可通信；不是CST求解错误。

## 实现与保证范围

GUI客户端被强制结束后，独立假Runner可继续完成；真实Qt离屏客户端进程也已做此对照。
假Runner被结束后重新启动进入需要恢复，不自动重放旧启动意图；标准/HOM检查点可显式续跑。
真实CST标准双任务在首项采用后停止，续跑首项TaskID不变。尚未对真实CST的每个Completion/received/Ack/采用窗口逐一终止控制器。
阻塞CST操作不即时抢占；仅工程.cst不足以保证三维场可读，旧无task-context会话不能凭空补接收。
可选场分析未完成的接收记录禁止直接当完整结果复用，不能为修复分析元数据而重放Solver。

## 未完成/推测

2026-10-15审计修复新增实测（合成执行，不是CST）：HTTP头收到但响应体未读即断开，服务端仍可能已经启动；服务端持久接受后延迟HTTP响应可触发客户端socket超时，二者都不能推断“未启动”。因此按稳定start请求ID对账，并通过服务端取消墓碑处理“查询未找到但请求迟到”的窗口。旧启动已完成后取消不能转而停止当前新run。
客户端端点元数据也存在并发边界：connect重置共享endpoint时，另一请求若反复读取该属性会遇None；改为请求局部快照后故障回归通过。
JSONL完整超长行不同于尚未写完的短尾行，后者等写入、前者有界跳过并留下原字节位置，不删除原始日志。
以上依据与剩余门禁见[审计修复](../docs/runner-audit-fix-20261015.md)。

WinError5还可能来自杀毒/索引/其他文件系统参与者，未证明唯一来源；不能无限重试掩盖真实权限问题。
Qt测试生命周期对照支持对象寿命与测试组合有关的判断，未做原生崩溃转储根因分析。
远程/多节点、跨用户控制和跨主机锁不在本轮实测范围。
